## Practical lineage — owner recollection

Mark previously used Puppy in donated-computer recovery arrangements: RAM-resident live operation, persistent configurations, optional USB storage and fallback to live operation. Windows retained. An installed Ubuntu choice was removed for ordinary recipients when boot selection increased support complexity. Image choices followed RAM and user needs.

“Emergency Plan A” meant recovery media kept with the machine so a software failure or unavailable drive need not remove basic web/email access. Historical experience, not a verified current build or credential-security recipe.

## Boundaries and lessons

First packet excluded archive rereads, networking, models, MCP, GUI and full Chamber security. Required real QEMU boot, serial-shell output, guest HELLO timing, sizes/hashes, failure controls and bounded stop. No guest was built in the source conversation; necessary host tools were missing.

Cheap-GPT suggestions: bounded inventory/extraction, docs/receipts, log triage, packet checks and test-bounded mechanical edits. Roles evolved; use [current workflow](../workflow/README.md).

Cost per accepted result includes failures/coordination/review/repair. Unknown costs mean incomplete coverage; bytes are not tokens. First observation alone establishes no gain.
